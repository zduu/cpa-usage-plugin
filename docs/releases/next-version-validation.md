## 2026-09-13 查询与传输阶段

源码和原始证据固定在[阶段目录](../validation/query-stage-20260913/README.md)。该阶段不是正式发布；后续改动须补充自己的验证记录，不复用旧二进制作为最终装载证据。

### 已实现和复查修复

- 范围摘要与 API 详情复用精确块汇总；完整范围块合并，边界逐条计算。缓存不持有请求数组，估算预算 8 MiB、最多 4096 项；追加、裁剪、归档块复制、修改、删除、重建、改价均接入失效。
- 复现并修复只排序而没有淘汰记录时的缓存失效遗漏，以及最近事件在同时间戳边界提前停止导致选错记录；满缓存回收扫描限制为每次查询一次，支持压力释放后重新准入。
- 补充独立旧实现参考、冷热/写入后查询、筛选、稳定排序、返回值所有权及缓存压力回归。
- 导入响应在发布导入结果的同一把锁内读取总请求/失败计数，不再为两个标量复制完整历史；覆盖归档、旧残差、大整数和并发导入。
- 真实 CPA HTTP 验证复现管理 JSON 的 HTML 转义使 ETag 回传失败（412）。分块任务改用安全的 opaque `version`，兼容原始或恰好一次 HTML 转义的旧 ETag；错误、空和双重转义版本仍拒绝。

Apple M1、macOS arm64、Go 1.26.6。三版本独立顺序运行，每项三轮、300 ms，以下为中位数；MB 是十进制分配字节量。

## 2026-09-13 完整备份、压缩传输与鉴权修复

完整源码补丁、原始日志、三轮真实 CPA 报告、两平台产物校验和及复现方法在[完整备份阶段目录](../validation/usage-export-stage-20260913/README.md)。原查询阶段保持冻结，不以旧产物替代本阶段验证。

### 已实现和复查修复

- 完整用量备份增加独立 `usage` 类型任务，冻结账本块、可见明细、聚合、配置和计数后逐条写出 v1 `ExportPayload`。保留残差和 accounting，不受事件筛选或 `export_max_records` 截断；与事件任务共享 2 个活动/16 个保留容量，列表、删除和下载按类型隔离。
- 支持 gzip 和最多 256 KiB 的有校验分块。支持原生解压流的浏览器自动压缩传输，再流式解压到 Blob；校验压缩块版本/长度/CRC32 及解压长度，最终仍保存普通 JSON。取消等待统计锁、文件 SHA 和失败半成品清理均已覆盖。base64 解码直接写字节缓冲，不再收集字符串迭代中间数组。
- 旧后端仅在任务创建端点不受支持时使用旧整包接口，保留原始 JSON 文本，避免前端再次舍入大整数；401/403/429/服务错误、网络、轮询和校验错误不回退。旧宿主发送前已损失的数值精度无法恢复。
- 真实 CPA 复现同实例备份回导重复计数：外部 hash 提前清除，导致已有带 hash 的可见明细和归档未匹配。修复在保留期限判断之后先检查导出 hash 对应的完整既有指纹；新记录继续旧跨实例规范化规则。回归保留不同客户端、时间、token、上游凭证和过期计数语义。
- 复查确认 **stock CPA 的 resource 路径不执行管理鉴权**。修复前 13 组匿名资源数据请求均返回 200，涉及旧统计/事件/价格/健康接口以及新备份任务；此前仅测 management 鉴权不足以发现此问题。现在只注册静态看板资源，所有数据及兼容回退均走管理路径，并拒绝宿主可能缓存的旧资源别名，包括伪造 Authorization 头的调用。该修复尚未发布或部署；旧版本访问限制见[管理 API 安全边界](../guides/cpa-usage.md#6-管理-api-使用)。

### 组件成本与内存

Apple M1、Go 1.26.6，同一候选进程、同一 10 万条 fixture，三轮 1 秒、中位数；每条样本实际 3–7 次操作。三条路径均写文件并计算 SHA-256。此处“旧”是候选内的旧编码流程，**不是 B0/B1 直接对照**。

| 完整备份生成路径 | 耗时 | 累计分配 | 文件大小 |
| --- | ---: | ---: | ---: |
| 旧快照展开 + 整包 JSON | 154.662 ms | 175.302 MB/op | 44.816 MB |
| 冻结流式文件 | 146.667 ms | 45.805 MB/op | 44.916 MB |
| 冻结流式文件 + gzip | 417.426 ms | 46.609 MB/op | 3.327 MB |

旧路径分配样本为 165.730–175.302 MB/op，不能只取某一轮；流式分配降低约 74%，但逐记录编码的分配次数更多。gzip 文件约缩小 93%，生成耗时约为未压缩流式路径的 2.85 倍，不能把传输优化描述成无 CPU 代价。

另以预编译测试程序各启动三个独立进程、每进程执行一次导出，轮换顺序。整个进程最大 RSS 中位数依次为 324.583 / 143.589 / 144.294 MB。该值包含 fixture 构建，不是导出增量，也不是 CPA 无插件/有插件配对；不能用约 56% 的组件进程差异宣布 G03 通过。运行时历史、可见明细副本和并发修改的冻结块仍会随数据增长。

### 真实 CPA 与浏览器

最终源码和 Linux 二进制一致的三轮独立验证全部通过：13 组匿名资源数据访问均为 404，管理鉴权下的查询、筛选、改价、冻结文件、回导、正常重启及已 fsync 增量的 SIGKILL 恢复成功。32000 条冻结备份回导新增 0、跳过 32000，保留后续新记录；最终恢复 32002 条 = 10000 可见明细 + 22002 归档。

Chrome 152 的完整备份均保留大整数、完整账本、按钮/筛选状态和任务清理；下面是同一管理鉴权边界下三轮中位数，不是正式高频 p95/p99。

| 14 MB 备份下载路径 | 传输文件字节 | 分块请求数 | 下载耗时 | 浏览器 JS 堆采样峰值 |
| --- | ---: | ---: | ---: | ---: |
| 压缩分块，无故障 | 约 0.457 MB | 2 | 0.827 s | 4.682 MB |
| 压缩分块，注入一次 503 | 约 0.457 MB | 3（含重试） | 1.163 s | 4.850 MB |

JS 堆每 25 ms 采样，备份前由测试回收垃圾；不包含原生 Blob 内存，也不是进程 RSS，可能漏掉短暂峰值。文件大小差异来自编码空白等，不代表缺失记录。压缩改善了本 fixture 的往返次数，但旧浏览器未压缩下载仍显著慢于旧整包路径，**该时延缺口仍未解决，G02 不判通过**。安全修复前资源路径不鉴权且不经过相同宿主响应处理，因此早期 6.39 s / 0.91 s 观测仅保留为问题发现证据，不与最终已鉴权路径混合计算收益。

最终完整 native/purego race（65.730 / 66.982 秒）、vet、163 项前端及更新脚本测试通过；Linux arm64 与 macOS arm64 共享库通过实际 stock SDK ABI 装载。完整补丁可从基点重建，已核对 84 个 Go 模块文件和 6 个支持文件。尚不代表 G01–G08 整体完成。

## 仍未完成

SQLite schema 3、状态事务、迁移暂存/解析和备份恢复目前只是基础层，运行时仍为内存 + JSONL + 快照。SQLite 权威历史接管、有界热数据/高基数分组、残差语义迁移、错误传播、激活与回退、全局资源预算及页面局部更新仍需实施。完整备份后台生成和分块下载已完成本阶段验证，但旧浏览器的未压缩时延、分块上传、大备份分批原子恢复仍未解决；旧导入仍单文件 50 MiB / 200000 条、整包解析。用量备份不包括独立价格文件，配置摘要也不会在导入时自动生效。

还需无插件/有插件单容器 CPU/RSS 配对、10 万/百万历史及高基数长文本、至少 24 小时稳态、最终五平台构建与实际装载、升级和含新数据的回退演练。保留既定 G01–G08，完成组件优化不等于总体达标。
