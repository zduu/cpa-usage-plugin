## 2026-09-13 SQLite 磁盘语义投影

### 实现和复查修复

- 已暂存 snapshot / JSONL 可建为磁盘节点、边和带校验的原文跨度，再按旧 Go 类型分页读取。保留重复字段、struct 合并、map value 替换、null 和 struct 数组复用语义，包括被截短后重新显露的隐藏尾元素；整数不经 float64。JSONL 元数据与无效行分类保留，不把真实相同记录误去重。

## 2026-09-13 SQLite 大记录前置能力

此阶段补齐旧数据迁移的一个前置缺口，不是运行时数据库接入。实现、故障复现、测量和装载记录仅保留本地；测试补丁、验证说明、日志和产物不纳入拟提交的实现补丁。

- schema 6 保留原有 `Apply` / `ApplyState` 的 1 MiB 单条契约，新增内部 `ApplyLargeState`。超过 64 KiB 的编码身份或请求值分为至多 256 KiB 的不可变块；引用、内容 SHA、记录、state、游标和 generation 同事务提交。多记录批次仍限 256 条 / 8 MiB；单个超过 8 MiB 的请求允许例外，并非硬内存或事务时长上限。
- 内容哈希只筛选候选，逐字节核对后才共享内容；真实请求始终有独立 ID。更新、归档和删除只检查本批触及的旧引用，无引用后回收块；冻结读视图仍能读取旧值。
- 先按逻辑字节预算选页，再读取分块。普通 inline 记录直接解码，避免另存一整页中间记录。缺块、错序、错误长度/SHA、错误 kind、marker/ref 不一致及伪造大小均报错；TEXT/NUL 字节长度防护同时覆盖两种构建。
- 复查修复身份行缺失时内连接静默漏掉历史的问题；新增值表、索引和外键定义核验，拒绝误接受同名但不兼容的扩展结构，并回滚版本升级。
- 真正 schema 3/4/5 旧库与旧备份（不含新扩展列）可升级；保留原记录、ID/revision、state、游标、generation 和暂存字节。大值备份恢复及中途写块、写记录、最终提交失败的全回滚通过。CGO 的 4 MiB SQLite 行保护未抬高；API/model/时区名的超大分组键仍未解决。

## 仍未完成

SQLite schema 6、大记录分块、状态事务、迁移暂存/typed 投影和备份恢复目前仍是基础层，运行时仍为内存 + JSONL + 快照，没有可启用 SQLite 的用户配置。SQLite 权威历史接管、有界热数据/高基数分组、残差应用、快照/JSONL 重叠及 metadata/protocol 协调、错误传播、激活与含新数据回退、全局资源预算及页面局部更新仍需实施。旧 `Apply` 的 1 MiB 单条契约继续保留，迁移大记录须显式选择新入口；超大 API/model/时区名及投影 map key、最大单值的内存/事务成本、不可达投影节点回收仍未解决；纯内存模式不得偷开磁盘。完整备份后台生成和分块下载已完成对应阶段验证，但旧浏览器的未压缩时延、分块上传、大备份分批原子恢复仍未解决；旧导入仍单文件 50 MiB / 200000 条、整包解析。用量备份不包括独立价格文件，配置摘要也不会在导入时自动生效。

还需无插件/有插件单容器 CPU/RSS 配对、10 万/百万历史及高基数长文本、至少 24 小时稳态、最终五平台构建与实际装载、升级和含新数据的回退演练。保留既定 G01–G08，完成组件优化不等于总体达标。

## 发布门槛

- G01：W01–R01 的功能、身份、计数、精确计价、可见性和失败语义符合契约。
- G02：原有路径不超过 B0 重复测量范围；完整功能不劣于 B1。高频场景至少 1 万独立样本、至少三轮。
- G03：预先固定主负载下，相对 B1 的插件增量稳定/峰值 RSS 至少降低 25%，CPU 至少降低 15%；另报 B0 绝对值。
- G04：数据库历史从 10 万至 100 万时常驻内存由声明预算主导；高基数、长文本及至少 24 小时稳态单独验证。
- G05：故障不静默丢数或重计，恢复边界不弱于现有 flush/fsync，任务可取消且资源可回收。
- G06：保留期限、导出容量、刷新频率和页面交互不缩水；浏览器及 ABI 端到端验证通过。
- G07：五种现有平台构建和相应宿主装载、升级恢复与版本匹配通过。
- G08：每项结论有对应源码、环境、原始证据和复现命令。组件分配量不代替 RSS，构建不代替装载。

全部门槛尚未通过，不更新正式 tag，不宣称已实现全面优化或绝对无缺陷。每轮记录复查范围、发现、修复和剩余项，直到发布审查不再存在已知阻断问题。
