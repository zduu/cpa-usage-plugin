## 1. 当前已有能力与待解决问题

以下能力在当前代码中已经实现，后续以保留和完善为主：

- 事件索引增量更新、稳定事件引用，以及恢复后同时间戳排序修复。
- 事件结果缓存 8 MiB 估算预算、索引数组 32 MiB 预算及待更新条数限制；这些不是插件总内存上限。
- 存储按最近任务截止时间唤醒，处理低流量刷盘、同步、快照及失败重试。
- 裁剪明细转入精简账本；导出冻结事件与成本，支持取消与清理。
- 凭据脱敏、更新插件原子替换及重启错误报告。

会话中对正式版与当前代码的本机对比，作为排查线索：

| 场景 | v2.6.4 | 当前代码 | 后续重点 |
| --- | ---: | ---: | --- |
| 10 万条数据，写入后刷新事件 | 5.35 ms | 2.60 ms | 保留收益 |
| 10 万条数据，上游接口详情 | 6.23 ms | 13.17 ms | 优先定位退化 |
| 10 万条数据，7 天范围汇总 | 53.8 ms | 63.9 ms | 减少全量扫描与重复计算 |
| 事件结果缓存命中 | 95.7 μs | 136.6 μs | 分析复制、计价及分配开销 |
| 10 万次请求、单模型、5000 条完整明细，GC 后存活堆增量 | 2.72 MiB | 18.07 MiB | 账本常驻内存成本 |

上述为 Apple M1/macOS 上三次测试的中位数；查询为组件基准，内存为合成数据实验，不是容器 RSS、CPU 或生产 p95/p99。内存实验未建立事件索引，不能靠调小查询缓存解决这项增长。接口详情基准未裁剪出账本，不能把其退化全部解释为保存了更多历史。混合查询和堆实验使用了临时测试文件，正式验收前须把生成器、命令及原始输出纳入可复现记录。

## 2. 优先级与实施次序

| 阶段 | 改进 | SQLite 依赖 | 完成标志 |
| --- | --- | --- | --- |
| P0 | 固定基准与热点剖析 | 无 | 退化归因有 profile 和复现实验支持 |
| P1 | 接口详情、范围汇总、缓存和索引优化 | 无，设计可供双后端复用 | 结果一致，消除已确认退化，保留已有收益 |
| P1 | 重复复制、内存分块和全局预算 | 无 | 相同负载下分配及峰值下降，不丢历史 |
| P2 | 导入导出、后台资源治理 | 短期无；完整历史分批读取可复用数据库 | 大任务不造成持续积压，结果与取消语义正确 |
| P2 | 页面局部刷新与运行诊断 | 无 | 页面状态保持，故障和资源瓶颈可定位 |
| P3 | 故障演练、兼容与交付门槛 | 按涉及后端分别验证 | 有可核验的功能、性能和升级报告 |

先完成 P0；P1 中每项单独测量收益再合并。SQLite 可独立开展驱动验证，但不能代替查询退化的修复。P2 的大任务优化与页面优化分别测量，最后由 P3 统一验收。

本专项编号映射到总计划：P0→总 P0，P1→总 P1/P2，P2→总 P3/P6，P3→总 P7。功能与资源验收遵循总计划 G01–G08；收益表以[统一结果文档](single-container-performance-results.md#收益预期与工程目标)为准，不另设较宽松门槛。

## 4. P1：查询与计价

涉及：`go/stats.go`、`go/accounting.go`、`go/event_index.go`。

- [ ] 完整明细按只读引用访问，紧凑账本直接参与聚合，减少反复构造和复制完整 `RequestDetail`。不得把可变内部对象暴露给调用方。
- [ ] 接口详情拆分为范围汇总、错误分布和最近事件计算；最近事件使用有序索引，避免为少量展示行扫描全部历史；各部分读取同一数据版本。
- [ ] 按时间分段维护精确汇总，完整分段直接合并，边界按逐请求时间补算。无法精确覆盖的组合筛选走索引，不使用近似统计。
- [ ] 限制预计算维度组合和高基数汇总的容量；不构造所有 API、模型、来源、凭证、客户端的笛卡尔组合。
- [ ] 根据 profile 缩减重复计价；改价仅重算受影响的模型、provider 与时间范围，保留价格接口返回时的一致性以及保存失败路径的当前语义。
- [ ] 细化数据、价格、币种及面板依赖的失效范围，继续校验时间窗口推进和 ETag；仅在证据支持时增加缓存。
- [ ] 验证紧凑记录 ID 与稳定分段索引，减少每个索引项重复持有的字符串和指针；保持迟到插入、相同时间戳顺序、修复和删除语义。

验收：全量与各筛选结果、错误分布、趋势、时段费用、排序和分页均一致；原先变慢的基准回到正式版重复测量范围内，同时保留持续写入后刷新的收益。先测锁等待，再决定如何缩短持锁时间，不直接把所有计算移到锁外。

## 5. P1：无需 SQLite 的内存改进

- [x] 移除 `captureEventExport` 在查询已返回独立副本后的第二次深拷贝，覆盖 Headers、Correlation、CostUSD 等可变字段的隔离测试。2026-09-10 工作区实现及 10 万条复制对照见[本轮结果](single-container-performance-results.md#本轮实现与实测2026-09-10-工作区候选)。
- [ ] 明细与账本按时间分块，到期时整块释放；部分块按空洞比例和字节阈值压实，避免每条请求都搬动整个窗口。
- [ ] 对重复元数据进行有边界的复用；现有身份字符串已部分复用，新增复用表需验证高基数场景不会反而扩大常驻内存。
- [ ] 给近期数据缓存、查询结果、索引、写入队列及后台工作缓冲设置独立字节计量与总预算；条数上限不能代替字节预算。
- [ ] 池化仅保留受限大小的缓冲，大对象任务结束后释放；评估预算淘汰对缓存命中率和查询时延的影响。
- [ ] 快照和完整备份逐块编码，避免一次把全部紧凑账本展开为完整明细再整体 JSON 编码；基于不可变分段或一致版本保持快照一致性。

验收：同时检查存活堆、临时分配、峰值 RSS、GC 和查询延迟，不只检查 `B/op`。纯内存模式仍随保留数据量增长，不承诺固定低内存；不得通过缩短保留期、删除账本或减少导出上限换取达标。

## 6. P2：导入导出与后台任务

- [ ] 生成阶段分批读取一致数据并写入磁盘文件。SQLite 后端使用一致性读取；内存后端需控制冻结分段的寿命及写时复制开销。仅冻结时间上界或最大 ID 不足以隔离修复和删除。
- [ ] 单独处理下载阶段的 `os.ReadFile` 与宿主 ABI 整包响应开销；验证追加的分块下载路径，保留旧接口并说明其剩余内存下限。
- [ ] 大导入分批解析、校验和暂存，整体成功后提交；失败或取消不能留下部分生效的数据，也不能静默跳过真实重复请求。
- [ ] 沿用已有取消能力，补查等待锁、捕获快照、编码、压缩、校验和及下载各阶段的取消响应与文件生命周期。
- [ ] 写入、快照、导入导出分别计量队列等待、工作字节数和并发压力；出现磁盘瓶颈时明确背压及错误报告，不静默丢记录或无限扩充队列。
- [ ] 在已有到期定时器基础上复查错误重试、文件轮转、配置重载和关闭排空；并发任务不能长期占住统计锁。
- [ ] 清理异常退出遗留的插件任务文件时，只处理有明确所有权、过期且不在使用中的文件；保留失败原因供诊断。

验收：文件内容、成本、数量、排序和截断规则不变；并发写入期间无重复、漏项或价格漂移；取消后资源可回收。浏览器可能仍需组装最终文件，服务端内存收益与浏览器收益分别报告。

## 7. P2：用户体验与可观测性

- [ ] 按面板的数据版本和依赖局部更新 DOM、表格及图表，减少整个页面的重复渲染；保持既有轮询间隔、手动刷新和切回页面刷新行为。
- [ ] 刷新保留筛选、排序、展开、滚动、焦点、语言及币种；继续在同一查询临时失败时保留有效旧结果，避免旧筛选数据冒充新筛选结果。
- [ ] 利用已有健康端点补充完整明细／账本数量、缓存字节数和淘汰次数、队列字节数及等待时间、后台任务占用。高频指标使用有界窗口，避免按客户端等高基数标签常驻累计。
- [ ] 区分可见明细、统计保留历史与已过期数据；提供简洁说明，避免用户把事件行数误认为累计请求数。
- [ ] 错误信息说明受影响功能和可执行处理步骤，例如只读目录、磁盘不足、导出过期；诊断数据不得包含原始凭据、请求正文或敏感路径内容。
- [ ] 评估导出／导入阶段进度和诊断详情是否确有必要。新增配置、通知或交互应独立列出评审，不作为性能优化的隐含附带变化。

验收：浏览器长任务和重复渲染减少，用户操作状态不丢失；诊断指标能解释资源问题，监测本身有可测且有限的开销。

## 10. 补齐端到端优化的实现细节

### 10.1 事件接收与查询热路径（W01/Q01/Q02）

- [ ] 记录回调只执行必要的归一化、聚合和入队，分析重复 hash、字符串处理及分配；不得移除脱敏或请求身份校验来换性能。
- [ ] 通过只读视图访问紧凑字段，结果所有权在 API 边界明确；缓存命中也要计入附加成本、克隆和 ABI 序列化的开销。
- [ ] 空结果和无效组合查询不能长期占满索引名额；评估按使用情况逐出和热点准入，避免维护无用索引、频繁全量重建。
- [ ] 深分页在后端使用稳定游标/索引位置；已有 offset 接口保持兼容，不能悄悄改变客户端分页合同。
- [ ] 分块压实与到期清理由固定工作预算调度；若对外延迟物理删除，逻辑查询和统计必须已按截止时间排除过期数据。

### 10.2 价格、汇率和外部请求（C01）

- [ ] 标准化价格查找表和规则解析结果按价格版本复用；时区、星期、跨午夜及 provider 优先级进入缓存依赖。
- [ ] 新价计算记录开始版本并追赶期间新增/修复/到期记录；再次改价应取消或取代旧计算，旧任务不得覆盖新版本。
- [ ] models.dev 和汇率请求复用现有条件请求、超时和退避能力，核对重载与关闭取消；失败不清空仍可用的价格/汇率，沿用陈旧与回退提示。
- [ ] 外部响应大小、解析内存及缓存条目有预算；合法大目录采用分批解析或受控暂存，不能默认截断现有价格查询结果。

### 10.3 快照、导出与传输（T01）

- [ ] 记录每阶段内存持有：冻结读视图、页缓冲、gzip、校验和、文件下载、JSON/base64 ABI 编码；优化要贯穿生成和传输。
- [ ] 分块请求携带任务 ID、文件版本、偏移/长度和校验信息；块可重试，文件不可在同一任务下静默替换。
- [ ] 鉴权、过期、取消、重复块、缺块、越界读取和跨任务访问有明确响应；失败任务不能下载半成品，旧整包接口继续兼容。
- [ ] 不让下载持有数据读事务；成功生成文件后释放数据版本，下载仅持有文件生命周期引用，防止清理与读取竞争。
- [ ] 内置看板处理二进制块，避免下载后完整 JSON 解析再编码；在支持的浏览器中选择有界写出，在兼容回退中明确并测量 Blob 组装内存。
- [ ] 上传分块落入未激活暂存区，校验完成后整体生效；幂等上传块不等于按内容去重真实 usage。

### 10.4 页面请求调度与渲染（U01）

- [ ] 为每类面板请求携带参数快照/请求代次；旧筛选的慢响应不能覆盖新筛选的快响应。可取消请求用 AbortController，无法取消的结果按代次丢弃。
- [ ] 合并同参数在途读取；手动刷新、轮询、切回页面同时发生时不重复拉取。修改价格等写操作不能合并或重放成多次提交。
- [ ] 依赖相同且数据版本未变的面板跳过 DOM/图表重建；更新变化节点而非替换整块，图表实例按需更新并释放旧监听器。
- [ ] 测量搜索输入、快速切换筛选、语言/币种切换和展开详情；必要的输入防抖不影响明确的手动刷新。
- [ ] 保持键盘操作、焦点、可读错误和窄屏布局；优化不改变表格行数上限或引入难以访问的虚拟列表。

### 10.5 可观测性、维护和故障（O01/R01）

- [ ] 指标区分明细/账本、缓存/权威数据、已接收/已提交/已同步、排队/执行耗时；健康查询本身不扫描全历史。
