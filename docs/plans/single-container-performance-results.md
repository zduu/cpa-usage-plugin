## 变更影响矩阵

| 变化 | 事件顺序/筛选索引 | 请求聚合/范围缓存 | 价格/货币 |
| --- | --- | --- | --- |
| 实时、迟到、真实重复 usage | 新增独立身份，增量插入 | 受影响分段和查询失效 | 采用当前价格 |
| 端点/流式元数据补充 | 身份和顺序不变 | 不改变计数，事件响应失效 | 不改变价格 |
| 导入、重放、历史修复 | 按已有语义重建或事务替换 | 同步重建受影响聚合 | 同版本重算 |
| 到期或明细转账本 | 删除可见引用 | 到期扣减；转账本保留统计 | 保留精确计价依据 |
| 改价（含保存失败） | 顺序/筛选不变 | 金额缓存失效 | 返回前同步更新价格版本 |
| 汇率变化 | 不变 | 仅相关响应元数据更新 | 更新货币版本 |
| 时间窗口推进、配置变化 | 边界重新校验 | 窗口/配置缓存失效 | 时区影响计价 |

## 已测参考：上一正式版 B0 与当前代码 B1

2026-09-09 会话中在同一 Apple M1/macOS arm64 上，B0 与 B1 顺序运行相同组件基准，三次、200ms，表内为中位数。以下是会话输出摘要，原始完整输出和临时补充测试尚未归档进仓库；它们可用于确定排查优先级，不能替代 P0 的可复现实验交付。

| 场景 | B0 v2.6.4 | B1 967915b | 已观察到的变化 |
| --- | ---: | ---: | --- |
| 写入一条后刷新事件，已有 10 万条 | 5.35 ms | 2.60 ms | 耗时下降约 51% |
| 上述操作的单次分配 | 1.71 MB | 0.13 MB | 分配下降约 92%，不是 RSS 降幅 |
| 摘要缓存命中，10 万条 | 18.1 μs | 17.4 μs | 范围重叠，基本持平 |
| 7 天范围汇总，10 万条 | 53.8 ms | 63.9 ms | 耗时增加约 19% |
| 事件查询，已有索引、无结果缓存 | 1.90 ms | 2.13 ms | 耗时增加约 12% |
| 事件查询，重建模型索引 | 4.97 ms | 5.96 ms | 耗时增加约 20% |
| 事件结果缓存命中 | 95.7 μs | 136.6 μs | 耗时增加约 43% |
| 上游接口详情，10 万条 | 6.23 ms | 13.17 ms | 耗时增加约 111% |
| 达到完整明细上限后的单条写入，单模型 | 1.93 μs | 2.35 μs | 耗时增加约 22% |
| 10 万次请求、单模型、5000 条完整明细，GC 后存活堆增量 | 2.72 MiB | 18.07 MiB | B1 保留了更多逐请求账本，约为 B0 的 6.6 倍 |

普通查询基准见 `go/main_test.go`，写入保留历史基准见 `go/resource_regression_test.go`。混合写入/查询与存活堆实验使用临时 overlay 测试，P0 必须固化到可追溯的测试入口和结果目录。

两项解释不可省略：内存实验没有建立事件查询缓存，调小索引预算不会消除这项账本增长；接口详情基准没有归档账本，其退化仍需 CPU/分配/锁 profile 归因。B0 比较用于揭示变化，但不能把 B0 未保留的逐请求历史视为完整功能已通过。

## 本轮实现与实测：2026-09-10 工作区候选

已在 B1 上实现查询筛选只读访问、查询内单项基础价格复用、API 详情普通价格去重计算和独立最近记录选择；
保留聚合遍历顺序、时段/星期计价、归档账本及返回副本隔离。移除索引项的闲置标记，64 位平台索引项从 80 降至 72 字节。
另移除导出第二次深拷贝、为过期账本大幅空置的底层数组增加收缩，并修复前端条件缓存/筛选汇总被过期响应覆盖的问题。
接口详情浏览器缓存现在最多保留 32 个选择；没有改变刷新频率、历史保留期或导出数量。

本次重新顺序测试 B0、B1 和候选，主要查询五轮、每轮 400ms，取中位数。B1 热/冷索引补充基准为三轮。
完整迭代次数、所有重复样本、源文件 SHA-256、环境及复现命令见
[组件实验目录](../../tests/performance/results/20260910-query-optimization/README.md)。首轮未完全解决的索引退化样本也保留，未与最终样本混算。

| 10 万条场景 | B0 正式版 | B1 改进前 | 本轮最终候选 | 相对 B0 耗时减少 | 相对 B1 耗时减少 |
| --- | ---: | ---: | ---: | ---: | ---: |
| API 详情 | 6.144 ms | 12.775 ms | 4.803 ms | 约 22% | 约 62% |
| 7 天范围汇总 | 52.818 ms | 58.118 ms | 50.354 ms | 约 5% | 约 13% |
| 事件筛选，索引已建但无结果缓存 | 1.874 ms | 2.063 ms | 0.591 ms | 约 69% | 约 71% |
| 事件查询，重建模型索引 | 4.950 ms | 5.596 ms | 4.377 ms | 约 12% | 约 22% |
| 事件结果缓存命中 | 94.411 μs | 133.244 μs | 84.914 μs | 约 10% | 约 36% |

内存与其他路径必须另报：

- 导出 10 万条的受控复制策略对照（其他路径一致）：两次复制约 92.81 MB/op，单次复制约 46.40 MB/op，分配量降低约 50%；耗时中位数 41.47→32.65 ms。不是整进程 RSS，也不是相对 B0 的整次下载收益。
- 最终冷索引单次分配约 2.27 MB，B1 约 2.48 MB，B0 约 2.05 MB；虽然低于 B1，仍高于正式版。事件结果缓存返回分配约 233.4 KB/op，仍高于 B0 的 225.2 KB/op。
- 账本收缩测试验证 4096 条历史大部分到期后，95 条归档记录的容量缩至 95，剩余 1 条可见明细及 96 条统计不变。此项回收闲置容量，不减少有效历史的逐条内存，不能替代 SQLite。
- 10 万条固定种子混合负载相对 B1：低基数范围汇总中位数 32.86→28.49 ms，写入后查询 1.61→0.705 ms；高基数写入后查询中位数 0.332→0.136 ms，样本波动较大。高基数范围汇总仍约 100ms、66.45 MB/op，未取得明确的分配收益，精确汇总和高基数字典优化仍需继续。
- 首轮普通写入与摘要缓存重复范围基本重叠；未将其宣传为加速。最终整进程 CPU/RSS、百万条/24 小时负载、启动/迁移/ABI 下载和浏览器时延尚未验收。

Bug 证据：新增前端测试先复现“旧缓存值 1 覆盖新值 2”和“相同筛选的旧汇总覆盖新汇总”，修复后通过；同时覆盖过期错误不污染当前页面、请求令牌释放及缓存淘汰。
Go 新回归覆盖同时间戳/迟到请求排序、账本计数、来源 Provider 选择、基础/时段/合成时间价格、导出可变字段隔离和到期容量回收。
全套 Go race、vet、前端 144 项测试和本地 darwin/arm64 共享库构建通过；不代表五平台宿主装载。

结论：本轮查询回退已有组件级改善，适合继续进入下一阶段验证；没有完成全方面优化，SQLite 尚未接入，不据此宣布可正式发布。

## SQLite 与安全升级的阶段进度（2026-09-10）

Go 工具链统一升至 1.26.6，修复安全扫描发现的三个可达标准库漏洞；默认 CGO 与纯 Go 对照重新扫描均无已知漏洞发现。之前的组件性能表仍是 Go 1.26.4 数据，最终收益必须在同版本工具链重新测 B0/B1/候选。

SQLite 基础层已实现一致视图、版本化事务、键集分页和身份字典；新增隔离暂存支持原文件分块复制、校验、失败恢复及 schema 1→2 升级。内存中的历史尚未由数据库接管。CGO/pure Go 的历史对照与平台证据见 [基础层记录](../../tests/performance/results/20260910-sqlite-foundation/README.md)，当前迁移边界和安全验证见 [本轮记录](../../tests/performance/results/20260910-sqlite-foundation/validation-go1266.md)。

相对上一正式版，本阶段预期改善升级可靠性和大文件迁移的临时内存增长；代价是额外暂存空间、校验 I/O 和驱动体积。不能宣称已经达到“RSS 至少降低 25%、CPU 至少降低 15%”，也不能据此宣布 SQLite 可启用或正式版可发布。

续进度：旧快照/日志已能逐项解析，单模型约 20 MiB 的测试验证首条交付前不必读取整个模型；不是 RSS 百分比结果。同时复现并修复现有 JSONL 恢复路径的无效快照部分入账问题，拒绝未知快照版本并保留出错目录供恢复。解析输出还未完成磁盘协调与业务接管，详见 [解析与恢复保护证据](../../tests/performance/results/20260910-sqlite-foundation/validation-stream-parser.md)。

| CPU | 精确汇总、减少复制和后台批处理共同达到相对 B1 至少下降 15% 的总目标 | 对 B0 的 CPU 降幅尚未知，不能把单次查询降幅当进程 CPU 降幅 | 单容器同负载长期实测 |
| 常规启动 | 避免每次全量加载和重建历史，预期大历史下更快、峰值更低 | 首次迁移可能更慢，须与常规启动分开 | 数据库打开、迁移、恢复与缓存预热分别测量 |
| 快照/备份与导出 | 降低全量展开和重复复制峰值，保持完整一致的文件 | B0 分页导出语义较弱，不能以恢复会漂移的分页换取低内存 | 生成、ABI 下载、浏览器组装各自验收 |
| 前端首屏与刷新 | 局部更新、合并在途读取、隔离过期响应，减少长任务和闪动 | 操作更稳定，刷新频率和功能不缩水 | 尚无浏览器对比数值，不给提速百分比 |
| 磁盘与插件体积 | 增加数据库/索引/WAL 和驱动体积，减少周期全量快照复制 | 存储结构与 I/O 模式改变，不承诺磁盘占用和二进制一起下降 | 报总字节、写放大、检查点和备份空间 |

预期总体收益是“大历史规模下资源增长更可控、常见操作保持或提高速度、统计与文件一致性更可靠”。不是保证每项指标无条件同时下降；具体路径未达到门槛时继续修复，不用总体描述遮盖退化。
