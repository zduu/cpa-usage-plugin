# 资源使用与实时兜底审查（2026-09-06）

本次修改基于插件 `3761aa3`，对照本地 CLIProxyAPI `5208aec7`。未连接 VPS、未部署或发布，结论来自源码、回归测试和本机基准。

## 兜底结论

对照的新版 CPA 可以取消插件的实时响应兜底，适用于所有模型，因此无需再保留非 GPT 白名单：

- `internal/pluginhost/adapters_usage_translation.go` 的 `usageAdapter.HandleUsage` 使用 `context.WithoutCancel`，避免请求取消导致已经生成的用量无法交付插件。
- `internal/runtime/executor/openai_compat_executor.go` 在翻译前观察原始 usage；流式函数通过 `defer streamUsage.Publish` 在退出时提交已观察到的用量，正常结束另有 `EnsurePublished`。
- `internal/pluginhost/adapters_executors.go` 为插件执行器提供非流式、流式、错误及取消路径的原生上报；通用解析位于 `internal/runtime/executor/helps/plugin_executor_usage.go`。
- `sdk/cliproxy/usage/manager.go` 异步投递已发布记录；用量适配器的取消上下文行为及插件执行器的上报已有测试覆盖，并已在本次运行验证。

插件关闭两项响应拦截能力，旧宿主若仍调用拦截 ABI，会得到空的成功响应，不解析载荷、不创建兜底。生产环境不再初始化实时协调器，原生上报不再扫描和重建其匹配索引。历史去重、导入、恢复测试保留。

边界：原生 usage 没有携带的元数据（例如某些 CPA 版本的 endpoint、stream 标记）不会再通过响应拦截补全；耗时和 TTFT 仍使用 CPA 原生字段。上游未提供的 token 无法由插件补算。此修改不承诺旧版 CPA、被禁用或熔断的插件、进程强制退出时仍可完整计数。

## 资源问题与修复

1. 旧插件按 schema 1 注册流式拦截。CPA 对旧协议每个分片复制、JSON/base64 编码请求体和历史分片，插件再次解码。关闭响应拦截后，这些工作不再由本插件触发。
2. 原先每条写入扫描全部模型明细，达到每模型上限后再复制全部保留明细。现在仅在最早过期时间到达时执行全局过期扫描，每次仅裁剪写入模型的窗口，利用切片容量摊销分配。
3. 淘汰和过期压缩清空底层数组中的引用，空窗口释放底层数组，防止响应头等数据被尾部引用保留。
4. 导入或重配置后的 dedup 表原先每条写入重复扫描；现在记录最早到期时间，到期后再清理。
5. 无匿名兜底的历史记录直接跳过匹配对象、token 形态索引和匹配图构建。
6. 响应头白名单读取移到统计锁内，修复记录写入与配置更新间的数据竞争。

明细数量上限、历史累计统计、过期记录的计数扣减语义保持原有设计。存储写入队列、导出任务数、价格下载大小及网络超时已有边界。本次未改变显式无限保留/无限导出的配置语义；实际内存仍取决于模型、上游及客户端维度数量、明细保留量、导入/导出大小，不能理解为进程 RSS 固定上限。

## 性能与验证

Apple M1 / darwin arm64，同一基准在原始提交的独立临时工作树与修改后运行，每模型预装 5,000 条明细，`-benchtime=300ms`：

| 保留模型数 | 原版写入耗时 | 修改后写入耗时 | 原版分配/次 | 修改后分配/次 |
| --- | ---: | ---: | ---: | ---: |
| 1 | 513 µs | 2.05 µs | 2,203,769 B | 2,034 B |
| 20 | 2,685 µs | 1.96 µs | 2,203,751 B | 2,047 B |

这是写入路径的微基准，不能直接等同 VPS 整体 CPU 或 RSS 降幅。

验证范围：Go 全量测试及 race 检测、go vet、c-shared 构建、前端 141 项测试；CPA 用量适配器及插件执行器回归。新增覆盖禁用拦截 ABI、明细引用释放、过期与数量限制、迟到记录、并发响应头配置、dedup 到期、原生历史无分配快速退出。旧版协议匹配、持久化恢复、导出及价格测试继续通过。
