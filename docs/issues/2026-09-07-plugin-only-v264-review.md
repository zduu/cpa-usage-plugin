# v2.6.4 插件内修复审查

## 范围与依据

变更仅在 `cpa-usage-plugin` 项目中。删除旧版本的 CPA 补丁及应用说明，保留本地提交历史。CPA 工作目录已有的修改未在本次操作中更改。接口依据为 Go 模块代理的 `github.com/router-for-me/CLIProxyAPI/v7@v7.2.152`，校验和记录在 `tests/stock-host/go.sum`。

该版本的 `pluginapi.UsageRecord` 没有 `Endpoint`、`Stream` 或请求 ID；已有的请求拦截回调带 `Metadata.request_path`、已选凭据、模型和 `Stream`。请求完成回调带请求 ID 与完成时间。插件据此维护有限的执行区间，只补齐原生用量元数据，原生上报仍是唯一计数来源。

## 审查发现及修复

1. 旧测试直接构造 `Endpoint`/`Stream`，不能证明未修改宿主可用。增加不含这些字段的 ABI 回归，以及使用未修改 SDK 加载实际共享库的联调程序。
2. 同一凭据的并发执行可能出现不同端点或流式状态。只有匹配候选一致时补齐；缺少信息、过期或候选冲突时保留未知，原生明确字段优先。
3. 淘汰仍活动的候选或容量溢出可能把歧义变成错误的唯一匹配。采用容量上限与暂停补齐机制，补齐停止期间计数照常。
4. 实际 SDK 解码发现 `status_code` 不匹配宿主的 `StatusCode`。管理响应同时输出两种字段，验证 200、304 和 404 能正确读取。
5. 重复运行发现极短请求的开始和完成时间可能相同。完成时间采用包含边界；重试切换仍采用排除旧区间的边界，并加入对应测试。

## 本地验证

- 插件全量 `go test -race ./...`、`go vet ./...`。
- `go test -run 'TestRequestMetadata' -count=100 ./...`：100 轮通过。
- Dashboard JS 语法检查与 141 项测试通过。
- 共享库构建后，用未修改 SDK 执行 `tests/stock-host`：四种请求路径、流式/非流式、取消后原生失败记录、两种回调顺序、`all`/`24h` 查询及 304/404 解码通过。
- 元数据回归验证原生计数不变，快照和实际 JSONL 恢复后字段保留。
- 现有记录/查询基准通过；本机 Apple M1 上 `BenchmarkRecordIncremental` 约 2.0 µs/op，10 万条明细的无明细摘要约 17.5 µs/op。这些是本机基准，不代表生产负载。
- 发布流水线增加 `go vet` 和未修改 SDK 的共享库 ABI 联调，作为多平台构建的前置检查。

## 明确边界

旧宿主缺少 usage 请求 ID，不能保证所有并发或 SDK 调用都能精确补齐端点。候选冲突、缺少身份/时间信息、缓存限制和历史空记录保持未知。缓存最多 4096 个执行区间，完成后保留 30 分钟；容量溢出或超时活动请求触发 30 分钟暂停补齐。详见[部署文档](../guides/cpa-usage.md#cpa-版本兼容与统计兜底)。

联调验证的是未修改宿主 SDK 与插件 ABI，不包含真实上游账户请求或已部署 CPA 实例的运行验证。最后一轮针对本次变更的代码审查未发现新增待修复问题；这不是对整个项目不存在缺陷的保证。
